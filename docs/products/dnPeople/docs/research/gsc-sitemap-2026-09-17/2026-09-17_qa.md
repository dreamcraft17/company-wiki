# Google Search Console Sitemap Research — dnPeople

## Conclusion

dnPeople already has the correct architectural entry points for a Next.js sitemap and robots file. The remaining operational work is to verify the deployed endpoints publicly, verify the correct GSC property, submit `sitemap.xml`, and monitor sitemap processing separately from URL indexing.

## Confirmed from official documentation

1. XML sitemap is supported and can be submitted through the Sitemaps report.
2. A single sitemap is limited to 50 MB uncompressed or 50,000 URLs; dnPeople is far below that based on the current route list.
3. URLs should be absolute and the sitemap should normally be hosted at the site root.
4. Sitemap submission is a hint and does not guarantee crawling or indexing.
5. URL Inspection and Page indexing are required for URL-level diagnosis.
6. Sitemap inclusion is a weaker canonical signal than redirects and `rel="canonical"`.

## Adversarial review

- **Could this be a deployment problem rather than an SEO problem?** Yes. DNS, TLS, WAF, login, or preview environment can make GSC unable to fetch the file.
- **Could a successful sitemap hide poor indexing?** Yes. Success only proves XML retrieval/parsing; use Page indexing and URL Inspection.
- **Could adding every route increase SEO?** No. Non-search pages and thin/duplicate pages can dilute the sitemap signal and create avoidable diagnostics.
- **Could dynamic `lastModified: new Date()` misrepresent freshness?** Potentially. Future implementation should use actual meaningful content modification timestamps where available; do not update `lastmod` on every request unless the content materially changed.

## Audit limitations

The production endpoint could not be live-verified from the current shell environment because DNS resolution was unavailable. The guide therefore marks live endpoint checks as a mandatory pre-submit gate instead of claiming production readiness.
