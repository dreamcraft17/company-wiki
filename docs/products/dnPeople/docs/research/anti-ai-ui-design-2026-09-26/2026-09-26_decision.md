# dnPeople UI direction — anti-AI-slop decision

Generated: 2026-09-26  
Research pack: `docs/research/anti-ai-ui-design-2026-09-26/`

## Decision

Move dnPeople toward an **Operational Editorial** UI: explicit enterprise controls and evidence density, with a warm/light working canvas, authored HR workflow motifs, and restrained brand color. Do not implement a literal retro/Y2K skin.

## Why

The strongest evidence does not say that old-looking UI is automatically better. It says that generic sameness erodes identity, while enterprise users need consistency, visible signifiers, and context-aware workflows. Flatness without signifiers is also a usability failure. Therefore the design should feel “older” only in its clarity and groundedness: labeled controls, visible state, rules, tables, and human-written operational language. This is consistent with [Built In’s critique of interchangeable AI UX](https://builtin.com/articles/ai-design-slop-era), [NN/G’s enterprise usability guidance](https://www.nngroup.com/articles/enterprise-usability/), and [NN/G’s flat-design findings](https://www.nngroup.com/articles/flat-design/).

## Visual rules

| Area | Adopt | Avoid |
|---|---|---|
| Canvas | warm white/off-white, quiet surfaces | full-page dark gradient, glowing blobs |
| Color | ink navy, teal/green semantic accent, amber/red status | indigo/purple gradient as decoration |
| Shape | mostly square/low radius, 1px rules | every section as a floating rounded card |
| Depth | one or two purposeful layers | arbitrary shadow on every card |
| Typography | tight hierarchy, readable regular/medium weights | tiny pale gray helper text, too many weights |
| Data UI | tables, rails, ledgers, evidence rows | dashboard card soup and decorative charts |
| Copy | branch/payroll/approval-specific language | generic “unlock”, “seamless”, “empower” filler |
| Motion | short feedback for state changes | ornamental animation and floating objects |

## First implementation slice

1. Rework marketing `/welcome` hero and proof section around the evidence-slip motif.
2. Rework shared marketing tokens: radius, shadow, surface, border, and brand color usage.
3. Rework dashboard section containers and payroll review rows to use rules and explicit state.
4. Keep data/business logic unchanged.
5. Run contrast, responsive, and screenshot checks before extending to every route.

## Evidence and design-system anchors

- Use [Material Design’s hierarchy and action principles](https://m1.material.io/) as a rationale for surfaces, edges, and meaningful motion—not as a visual template.
- Use [Apple’s typography guidance](https://developer.apple.com/design/human-interface-guidelines/typography) for readable weights and a limited type system.
- Use [NN/G’s clickability guidance](https://www.nngroup.com/articles/clickable-elements/) to preserve signifiers while reducing decorative chrome.
- Use [Creative Bloq’s design-history synthesis](https://www.creativebloq.com/design/a-quarter-century-of-design) only for historical inspiration; validate every pattern against HR task usability.

## Acceptance bar

- A reviewer can identify what is actionable without hover hunting.
- A reviewer can distinguish status, warning, and selected state by more than color alone.
- No route has more than one decorative gradient/hero treatment.
- Core HR workflow terms appear in visible hierarchy, not hidden inside generic cards.
- WCAG AA contrast is preserved; touch targets remain at least 44px where applicable.

## Adversarial review

- Risk: “operational editorial” becomes a new monochrome template. Mitigation: use real dnPeople evidence and a small set of intentional accent moments.
- Risk: density harms mobile. Mitigation: preserve responsive stacking and test mobile-first flows.
- Risk: low radius is mistaken for old/cheap. Mitigation: keep typography, spacing, and interaction polish modern.
- Risk: removing shadows removes hierarchy. Mitigation: retain border, surface, and limited layer signifiers.
